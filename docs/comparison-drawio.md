# staruml-mcp compared with jgraph/drawio-mcp

[jgraph/drawio-mcp](https://github.com/jgraph/drawio-mcp) is draw.io's own set of integrations:
an MCP Apps server (`create_diagram`, `search_shapes`, hosted at `mcp.draw.io`), an MCP tool server
(`@drawio/mcp`: `open_drawio_xml`, `open_drawio_csv`, `open_drawio_mermaid`, `search_shapes`, page
tools), an agent skill for Claude Code, Codex and Copilot, and project instructions. This page
compares it with staruml-mcp 0.4.0 plus staruml-mcp-extension 0.3.0 (the hqqw2h-lgtm forks). Both are good at
different things: draw.io draws pictures of anything, StarUML keeps a UML model behind its
diagrams.

Read against drawio-mcp's `main` branch as installed in October 2026; token counts are o200k_base
(`gpt-tokenizer`), measured on its `shared/*.md` and our listing with `npm run benchmark:tokens`.

## Feature by feature

| Area | drawio-mcp | staruml-mcp + extension | Gap, and what is planned |
|---|---|---|---|
| **What a diagram is** | A drawing: cells with styles and coordinates in `.drawio` XML. Any subject (cloud architecture, network, UI mockups, floor plans). | A view of a UML model: classes, actors, states and relationships exist once in the `.mdj` project and can appear on several diagrams. UML, ERD, flowchart and mind map kinds only. | draw.io cannot answer "which classes depend on Order" across diagrams; StarUML cannot draw an AWS architecture. Neither closes this gap; it is the products. |
| **Inline viewer** | MCP Apps view of the real draw.io viewer: renders the diagram, runs ELK/libavoid passes, offers "Open in draw.io" for editing. Hosts: Claude.ai, VS Code, Cursor, any MCP Apps host. Falls back to an `app.diagrams.net` link. | `view_diagram` + `ui://staruml/viewer.html`: the SVG StarUML exports, with pan, zoom, fit, dark mode and the diagram name; no external requests. Falls back to a PNG image block. | Ours is read-only and cannot hand the diagram to an editor in the chat; the user edits in StarUML. Over HTTP the viewer needs a session (#14); a request without one gets the PNG. |
| **Shape and type search** | `search_shapes` over 10,000+ stencils (AWS, Azure, GCP, Cisco, UML, BPMN, ...) plus an icon service. | `search_types` (through `call_endpoint` since 0.6.0): fuzzy search over the metamodel types, palette items, relationship kinds and commands of the running StarUML, each hit with an example request body. | Ours searches what StarUML can create, not icon sets; there is nothing like vendor stencils to search. |
| **Input formats** | draw.io XML; CSV (tool server); Mermaid, about 20 diagram types rendered natively by the app server, converted by the draw.io CLI in the skill. | `build_diagram` from a per-kind JSON spec (class, sequence, use case, activity, state machine, ERD, flowchart, mind map); Mermaid `classDiagram`, `sequenceDiagram`, `flowchart`/`graph`, `erDiagram`, `stateDiagram` through the extension and 7 types through StarUML's built-in importer; element-level CRUD for everything else. | No CSV, no free-form XML, far fewer Mermaid types. Extension #16 adds PlantUML, SQL DDL to ERD, JSON Schema to class/ERD, Mermaid C4 and requirement diagrams; #19 Mermaid notes and styles, nested states. |
| **Reading a diagram back** | The model wrote the XML, so it has it; `get_page` returns one page's XML from a file. | `diagram_as_text` (Mermaid, which `build_diagram` reads back, or PlantUML) and `staruml://diagram/{id}.mmd` / `.puml`; `describe_diagram`, a bounded summary of nodes, members and edges; `find_elements` / `get_element_by_id` summaries with `fields` and `depth`, the `staruml://project/tree` resource, PNG/SVG export. A six-class diagram reads in about 270 tokens as text against an estimated 1,600 as a PNG (README, "Reading a diagram back"). | Text export leaves out what the notation cannot carry (notes, styles) and says so in `warnings`. |
| **Layout** | ELK layered layout (`postLayout: "elk"`, direction) and libavoid obstacle-avoiding edge routing (`routing: "libavoid"`); the skill exposes the draw.io CLI's layout presets. | StarUML's own auto layout after every `build_diagram` with `direction` TB/BT/LR/RL, `layout_diagram`, `move_views`, `resize_node`; sequence diagrams, lanes and boundaries placed by computed geometry. | `layout_diagram` presets (`flow-*`, `hierarchy-*`), node and rank separations and `fit`, `route_edges` for one line style on every edge, and `build_diagram`'s `layout`; still StarUML's dagre layout, with no obstacle-avoiding router. |
| **File and page operations** | `list_pages` / `get_page` / `set_page` on a local multi-page `.drawio` file; the skill writes `.drawio` files and exports PNG/SVG/PDF with the XML embedded through draw.io Desktop. | Project `new` / `open` / `save` / `save_as` (`.mdj`), diagram create / switch / close, export of one diagram as PNG/JPEG/SVG, many diagrams to a directory, PDF, HTML documentation; code generation and reverse engineering through StarUML's language extensions. | Exports are not re-importable the way draw.io's embedded-XML PNGs are; the `.mdj` is the editable artifact. |
| **Validation** | XML normalized and checked before rendering; malformed XML is refused with a message. | Every request body checked against the extension's JSON Schema (unknown keys refused) before it is sent; `batch` ops and `$name` references checked before the first op runs; the extension validates each `build_diagram` spec per kind. | `validate_model` (through `call_endpoint` since 0.6.0) runs StarUML's validation rules on the open model and lists problems with element and rule ids; draw.io has no model to check. |
| **Undo** | None in the MCP layer; a diagram is replaced or reopened, and the draw.io editor has its own history. | Each `build_diagram` and atomic `batch` is one StarUML undo step and rolls back on failure; `undo`, `redo`, `is_modified` endpoints. | `upsert` adds and updates but never deletes; extension #19 adds `prune`. |
| **Security** | App server is remote by default (`mcp.draw.io`), so the diagram leaves the machine unless self-hosted; the viewer loads draw.io code from `viewer.diagrams.net` (inlinable at build time); declared CSP domains. Tool server keeps the diagram in a URL fragment. | Local: nothing leaves the machine. The extension binds to 127.0.0.1 and has an optional access token (`STARUML_EXT_TOKEN`, or `--ext-token`, which other local users can read in the process list), Origin and Content-Type checks, payload and rate limits, a time-out per request, all with error codes the server explains. The viewer makes no network requests and shows the SVG as an image, so element names cannot inject script. | StarUML 7.1.1's built-in API listens on every interface (`*:58321` in `lsof`) without authentication and cannot be told otherwise; the README shows how to block it at the host firewall. This server's `--transport http` binds `127.0.0.1` and refuses non-loopback `Host` and `Origin` headers unless `--host` says otherwise, which it warns about. `execute_command` can run any StarUML command; dialogs are refused, but the token is the only gate for other local processes. |
| **Token cost of the tool list** | `create_diagram`'s description embeds the XML and Mermaid references: 9,274 + 4,282 tokens, resent with every turn by clients that do not cache. | Core tier: 19 tools and the instructions in 1,973 tokens, enforced by a test; the remaining 69 endpoints are reached through `describe_endpoints` / `call_endpoint`. Results are compact JSON without nulls or echoed arguments; images are image blocks, the viewer's SVG stays out of the model's context. | Our long grammar lives in the skill (7,746 tokens, loaded only when the skill triggers) and `describe_endpoints`. |
| **Agent skill and plugins** | `drawio` skill (6,311 tokens) with Claude Code, Codex and Copilot plugins from one marketplace repo; OpenCode reads it directly. | `staruml` skill with the same three plugin layouts, generated from one source by `npm run sync:skills`; the Claude Code plugin also registers the MCP server. Every tool call in the skill is run by the test suite against stand-ins and, with `STARUML_LIVE=1`, against StarUML. | — |
| **Requirements** | Nothing for the hosted app server; draw.io Desktop for the skill's file exports. | StarUML 7 running on the same machine with its API server enabled; staruml-mcp-extension 0.3.x for everything beyond Mermaid import and PNG. | StarUML must be running; there is no headless mode. |

## When to use which

- A UML model that should stay consistent, be queried, generate code or be refactored across
  diagrams: staruml-mcp.
- A one-off picture, an architecture or network drawing with vendor icons, a diagram type UML does
  not have, or zero install in Claude.ai: drawio-mcp.
